### 4.6 等待无超时：两条独立复现

**复现 A（多车抢同一工位）**：三张任务都取 `A01-DOCK (0,0)`，AGV-01 先到并停在 (0,0)，03/04/02 依次堵死；`since` 从 15:56:01 一直保持到 16:01 手动取消，**约 5 分钟零进展**。

**复现 B（返回待命区被空闲车挡住）**：取消积压任务后单建一单 `AGVT20261126069`，AGV-01 卸完货回待命区 (0,1)，而 (0,1) 被**空闲**的 AGV-03 占着、(0,2) 是 AGV-02、(1,1) 是 AGV-04 —— 四个邻格全占，AGV-03 的「让行」找不到空格，于是：

```
16:04:24  waiting=1  AGV-01 等待 AGV-03 让出格子(0,1)   (已 37 秒)
          task AGVT20261126069 st=5 返回待命区    ← 永远到不了 6 已完成
```

即：并非死锁环，只是一台空闲车挡路，任务就永远停在 `返回待命区`。

## 三、缺陷清单（按严重度）

| # | 严重度 | 现象 | 代码位置 | 建议修法 |
| --- | --- | --- | --- | --- |
| D1 | 高 | 「格子被占用」等待无超时，可无限等待 | `AgvEngineService.java:442-451`：`owner != null` 分支只 `markWaiting` + `waitGraph.put`，不像 424-429 / 432-441 那样比较 `WAIT_REPLAN_MS` | 该分支同样累计等待时长，超过 `WAIT_REPLAN_MS` 后：先 `clearPath` 强制下一 tick 换路，再超时则 `recycleTask`，或把挡路车标记为「需让行」强制调度 |
| D2 | 高 | 让行只找 1 跳邻格，四邻全占即返回 false，空闲车互相围死 | `findFreeSideCell:765-782`（只扫 4 邻接）、`tryYieldIdle:788-808`（`free == null` 直接 return false） | 改成多跳：BFS 找最近的空格并把挡路车串行推开（chain yield），或允许「先退一格再让别人」的两段式让位；实在无解则回收请求方任务并告警 |
| D3 | 中 | 空闲车没有出边时不构成有向环，死锁检测看不到 | `findCycle:712-731`：沿 `waitGraph.get(cur)` 走到 `null` 即结束 | 把「等待图 + 车是否 IDLE」一起判：若某车的 blocker 是 IDLE 车且该 blocker 无出边，则直接判为「被闲置车阻塞」并强制让行 |
| D4 | 中 | 无空格可让时无限回收同一任务（活锁），日志刷屏 | `detectAndBreakDeadlock:702-706` 每 tick 都可能再次回收 | 同一任务回收后要加冷却窗口（例如 30 秒内不再派给同一批车），或改判「重新分配优先车辆」，避免同任务反复回收 |
| D5 | 低 | 改派后时间线时间戳乱序 | 时间线数据出自 `wms_agv_task` 各阶段时间列 | 回收/改派时清空后续阶段时间戳，或时间线按状态序号而非时间排序 |

> 补充：后端重启**不能**清现场——车辆坐标与任务状态都落库（`wms_agv_device` / `wms_agv_task`），重启后同样的死锁会立刻复现。可用的恢复手段只有前端「取消」任务。
