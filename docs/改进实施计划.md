## 阶段验收与 GitHub 交付流程（强制）

> **一句话**：每个阶段做完 → 跑验收脚本 → 全绿 → 在本文档打钩 → 提交并推送 GitHub（写清楚改了什么）→ 核对远端提交号。**没有验收证据的“完成”不算完成，没有推送的“交付”不算交付。**

### 一、每个阶段的固定动作（顺序不可颠倒）

1. **构建**：`mvn -q -DskipTests package` 必须退出码 0；前端如改动需 `npm run build` 通过。
2. **跑验收**：启动后端后执行本阶段的验收脚本（见下表），脚本必须**全部通过**，并把实际输出写入 `docs/evidence/阶段N-*.md`。脚本失败时先修复、再重跑，**不得跳过或手工改结论**。
3. **对照判据**：逐条核对本阶段「完成判据」与各条目的「→ 验收」，全部满足才允许打钩。
4. **打钩确认**：把本文档对应条目的 `- [ ]` 改为 `- [x]`，并在条目末尾追加 `✅ YYYY-MM-DD 验收：docs/evidence/阶段N-*.md`。
5. **提交**：`git add -A` → `git commit`，提交信息格式见下；一个阶段一个提交，不跨阶段混提。
6. **推送**：`git push origin master:main`（远端 `https://github.com/K-IRIN/wms.git` 的 `main`）。
7. **核对**：`git ls-remote origin main` 的提交号必须与本地 `git rev-parse HEAD` 一致；不一致时查明原因并解决，**推送失败必须明确告知用户，不得宣称已交付**。
8. **记录**：在下方〈阶段交付记录〉表格追加一行（日期 / 阶段 / 提交号 / 验收文件 / 主要更改）。

## 阶段 4：多车冲突（12-08 ~ 12-12，3.5 人天）

> **目标**：这是开题关键技术 4 的核心，也是 v1.0 方案里最大的缺口——当前 `moveToward`(247-274) 全程不查占用，两车可以互穿。做完本阶段，论文第 5 章才有“冲突消解”可写。

- [ ] 4.1 显式路径队列：把“先横后纵”的临时走法改成按任务算一条路径（BFS 足够，不必上 A*），任务存路径队列，跨 tick 续走
      → 验收：双通道地图上路径正确，切格不丢进度，重规划后路径可回溯
- [ ] 4.2 双格预留占用表：以 `(x,y)` 建内存占用表，随 tick 重建；推进前检查“当前格 + 下一格”
      → 验收：同一 tick 两车不会进入同一格
      → 注意：`AGV-03` 的 `speed=0.8`，`moveToward` 用累加器做分数移动，一个 tick 可能走 0 格或多格——只判“当前格”必然出现同格重叠
- [ ] 4.3 死锁检测与打破：维护等待图，成环时按“紧急优先 → 距离近优先 → id 小优先”强制一方回退待命
      → 验收：环形等待能在 10 秒内自行解除，并留下冲突事件日志
- [ ] 4.4 阻塞格模型：现有 `blockTicks`(315-328) 与 `injectBlock`(450-455) 是“整车暂停 10 秒”，与“通道被占”不是一回事；改为“格子被标记阻塞 → 路径绕行或等待超时重规划”，注入入口复用现有 `/agv/fault/inject`
      → 验收：标记某格后，经过该格的任务绕行；无法绕行时 10 秒后重规划或退回
- [ ] 4.5 状态转换表校验：`changeTaskStatus`(222-228) 目前无转换表，任意流转都能写库；补 8 态转换矩阵，非法流转拒绝并记日志
      → 验收：8 态转换表逐条可通过，非法流转返回明确错误
- [ ] 4.6 前端等待标识：地图上给等待/阻塞的车加呼吸光圈与“等待中”标签
      → 验收：录像里一眼能看出哪台车在等

# 附 D：指标口径

| 指标 | 口径 |
|------|------|
| 设备利用率 | 各车执行任务时长之和 ÷（车辆数 × 统计窗口时长）× 100%；任务时长取 `startTime` 到 `endTime` |
| 任务完成率 | 已完成任务数 ÷ 创建任务总数 × 100%；取消任务计入分母、不计入分子 |
| 平均完成时间 | 所有已完成任务的（`endTime − startTime`）之和 ÷ 已完成任务数，单位秒 |
| 空驶率 | 前往取货段行驶里程 ÷ 总行驶里程 × 100%；需阶段 5 的里程采集，未采集时该指标不写进论文 |
| 冲突次数 | 等待事件计数 + 重规划次数；等待事件在占用检测未通过时自增并写 `wms_agv_log` |
| 告警次数 | `wms_agv_log` 中类型为“告警”的记录数；论文中需说明是累计值而非比率 |
