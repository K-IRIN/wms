# WMS 毕业设计 —— 问题记录总结

> 记录从项目初始化到二期 E2 阶段开发过程中遇到的典型问题、排查过程、根因与解决方案。
> 可用于论文"系统测试与问题解决"章节及答辩问答准备。
> 按类别分组，每个问题含：现象 → 根因 → 解决 → 经验。

---

## 一、后端类问题

### 问题 1：WebSocket 推送只能收到第一条，之后全部丢失（E2 阶段，最典型的 bug）

- **现象**：浏览器连接 `/ws/agv` 成功，创建 AGV 任务时能收到 1 条推送，之后调度引擎每秒广播的 AGV 位置/任务状态全部收不到。直连后端 8080 复现，排除前端代理问题。
- **排查**：在引擎代码里打断点/加日志确认 `broadcast()` 确实被调用了；检查会话集合正常；最后怀疑到 JSON 序列化环节。
- **根因**：`AgvWebSocketHandler` 里用的是 `new ObjectMapper()` 裸实例，没有注册 `JavaTimeModule`。创建任务时推送的内存对象 `createTime` 为 null，所以能序列化成功；而引擎每秒广播的是从数据库查出的对象，带 `LocalDateTime` 字段，序列化直接抛异常——且 `catch (Exception e) { return; }` 把异常**静默吞掉**了，没有任何日志。
- **解决**：改为注入 Spring 容器配置好的 `ObjectMapper`（自带 `JavaTimeModule`）；同时把静默 catch 改为 `log.warn(...)` 记录失败原因。
- **验证**：修复后 12 秒内收到 15 条推送（task/agv 交替），与引擎节拍一致。
- **经验**：① 时间类型序列化是 Jackson 高频坑，永远用 Spring 管理的 ObjectMapper；② **catch 块里至少要打日志**，"静默失败"是排查噩梦；③ 二分法定位：先确认"发没发"，再确认"收没收"，逐段排除。

### 问题 2：Windows 下 Maven 打包报错 "Unable to rename jar"

- **现象**：后端代码改完后 `mvn package` 失败，提示无法重命名 jar 文件。
- **根因**：旧版本后端 Java 进程还在运行，占用着 `target/wms-server.jar`，Windows 的文件锁机制不允许替换被占用的文件（Linux 无此问题）。
- **解决**：打包前固定先杀进程：`netstat -ano | grep ":8080" | grep LISTENING` 找到 PID → `taskkill //PID xxx //F` → 再打包 → 再启动。
- **经验**：形成"杀进程 → 打包 → 启动 → 看日志确认 Started"的重启铁律，写入操作手册，此后再没犯过。

## 二、前端类问题

### 问题 3：登录页验证码图片不显示

- **现象**：登录页验证码区域空白，无法登录系统。
- **根因**：后端已把验证码图片转成 base64 并带好了 `data:image/png;base64,` 前缀，前端又拼接了一次前缀，导致图片 src 非法。
- **解决**：去掉前端重复拼接（commit `80d3144`）。
- **经验**：前后端约定数据格式时，"谁负责加前缀/单位/格式化"要写清楚，双方都加就会出错。

### 问题 4：浏览器自动化调试时取不到登录 token

- **现象**：脚本里 `localStorage.getItem('token')` 拿到 null，接口全部 401。
- **根因**：项目前端存的 key 叫 `wms-token`，不是想当然的 `token`。
- **经验**：调试前先读源码确认存储 key、接口路径、请求头格式这些"约定"，不猜。

### 问题 5：界面初版过于简陋、物料看不到存放位置

- **现象**：早期版本界面朴素、图标不美观；物料管理列表只有名称规格，不知道物料放在哪个库位，不实用。
- **解决**：阶段 14 整体做科技风美化（主题/布局/登录页/看板/时间格式），物料列表增加"所在库位"列（commit `4fbf7f6`）。
- **经验**：从"实际使用者"角度审视系统——仓库管理员最关心的是"东西在哪"，功能要做进使用场景里。

## 三、数据库 / SQL 类问题

### 问题 6：大 SQL 文件编辑时工具匹配失败

- **现象**：用文本替换方式修改 `sql/wms.sql` 时，明明内容存在却匹配不到。
- **根因**：文件经过多次编辑后 CRLF/LF 换行符混杂，精确匹配被换行符差异破坏。
- **解决**：结构性追加改用 `cat >> 文件 << 'EOF'` 方式，避免对旧内容做精确匹配。
- **经验**：多人/多工具协作的文件保持换行符统一（项目已用 `.gitattributes` 思路规避）；追加优于替换。

### 问题 7：库位坐标需要手工换算，容易填错（E2 阶段顺手优化）

- **现象**：E1 给库位加了平面坐标（AGV 寻路要用），新增库位时人工按编号换算坐标很反人类。
- **解决**：新增/编辑库位时后端按编号规则自动解析坐标（如 `A02-03-01` → 坐标 (1,3)）。
- **经验**：能由规则推导的数据就不要让人填，减少出错面。

## 四、Git / 版本管理类问题

### 问题 8：git push 被拒绝（远端有新提交）

- **现象**：`git push` 报错 `rejected ... non-fast-forward`。
- **根因**：同一仓库在两个环境（本地 + 云端网页端）都改过文件，远端有了本地没有的提交。
- **解决**：`git pull` 合并远端变更（产生 merge commit `7083d9b`）后再 push。
- **经验**：养成"先 pull 再 push"的习惯；计划文档等多处同步的文件，改完立刻提交推送。

### 问题 9：sed 批量勾选计划清单时误勾其他章节

- **现象**：用 `sed 's/- \[ \]/- [x]/'` 批量勾选完成项，把还没到阶段的章节（论文阶段）也勾上了。
- **解决**：正则加锚定，只匹配行首带阶段前缀的项，如 `sed -i 's/^- \[ \] E2\./- [x] E2./'`。
- **经验**：批量替换前先 `grep` 看会命中哪些行；正则越精确越安全。

### 问题 10：Git Bash 路径格式导致命令失败

- **现象**：脚本里用 `E:\毕业设计\WMS` 或 `/e/毕业设计/WMS`，部分工具/命令识别失败。
- **解决**：Git Bash 内统一用正斜杠形式 `"E:/毕业设计/WMS"`；需要 Windows 原生路径时用 `pwd -W` 获取。
- **经验**：跨 shell 环境（Git Bash / cmd / PowerShell）操作前先确认各自的路径写法。

## 五、环境 / 协作效率类问题

### 问题 11："项目怎么启动？为什么运行不了？"

- **现象**：开发一段时间后，启动步骤变多（MySQL、后端 jar、前端 dev server），容易漏步骤，报错也不知道看哪。
- **解决**：编写了**一键启动脚本**（commit `80400a1`），双击即可按顺序拉起前后端；同时 README 里写清完整启动指南与常见问题。
- **经验**：把重复 3 次以上的手工步骤脚本化；启动类文档是"未来的自己"最需要的东西。

### 问题 12：后端重启后要重新登录吗？——JWT 无状态特性

- **现象**：调试中发现后端重启后旧 token 依然有效，一度怀疑"是不是鉴权失效了"。
- **结论**：这是 JWT 无状态设计的正常表现——token 的合法性靠签名验证，不依赖服务端会话，服务端重启不影响已签发 token（直到过期）。
- **经验**：理解技术选型的特性，把"疑惑"变成"论文里的设计说明素材"。

## 六、方法论总结（可直接写进论文）

1. **定位问题的二分法**：先在数据链路上分段确认（发没发 → 传没传到 → 收没收 → 渲没渲染），每段用最小实验验证，避免盲目改代码。
2. **静默失败是万恶之源**：所有 catch 至少记日志；后台线程的异常尤其要显式记录。
3. **约定大于猜测**：前后端数据格式、存储 key、接口路径，以源码为准。
4. **重复即脚本**：重启、启动、提交、勾选计划等固定流程全部固化成命令/脚本，降低人为失误。
5. **版本控制即保险**：每个功能点提交一次，出问题时可以快速回退定位；dev/main 分支隔离开发与正式版本。
